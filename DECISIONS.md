# Decisions

| # | Date | Decision | Why | Alternatives rejected |
|---|---|---|---|---|
| D1 | 2026-11-16 | Use SNCF G&C NeTEx + lift status as the lift layer | Public, ODbL, 100 % id join lift↔status, three-valued status, quay-level assessments | IDFM elevator data (needs key); GTFS pathways (no lifts) |
| D2 | 2026-11-16 | Derive lift→space edges from lift location text, label each edge | Only available topology; labelling keeps it honest and auditable | Inventing pathways; geometric proximity |
| D3 | 2026-11-16 | Pairs = platform↔platform and platform↔exit inside a station | Matches what a lift actually enables; bounded and explainable | All node pairs; cross-station journeys (no platform↔line mapping in open data) |
| D4 | 2026-11-16 | Pilot = all SNCF stations in IDF (401), spotlight Juvisy-sur-Orge | Data-dense, bounded, real current KO lifts to rank | A single famous hub chosen for recognisability |
| D5 | 2026-11-16 | Single-file `.rl` store, one owner thread, uvicorn workers=1 | Relate is thread-affine with a single-writer lease | Multi-worker server, separate DB |
| D6 | 2026-11-16 | Cache minimal lift sets per pair after one Relate traversal; evaluate scenarios in pure Python | ms-level scenarios; the traversal and evidence still come from Relate; cache rebuilt from the store | Re-running a 3 s traversal per click |
| D7 | 2026-11-16 | "Blocked" when every modeled route needs an unavailable lift, with explicit scope text | Faithful to modeled criteria; UI states that undocumented ramps could exist | Calling it UNVERIFIED (would hide real outage effects) |
| D8 | 2026-11-16 | Freshness displayed, not folded into classes | Keeps replays reproducible; staleness still visible | Downgrading stale snapshots to UNVERIFIED |
| D9 | 2026-11-16 | No composite score; rank by Δ confirmed pairs only, exact k-repair planner | No verifiable cost/ridership data | Weighted scores |
| D10 | 2026-11-16 | Runtime AI optional and number-validated | Core must work without keys; prevents fabricated figures | Chatbot over raw data |
| D11 | 2026-11-16 | Commit normalized snapshot + snapshot store (ODbL) | Judges can run and inspect offline in seconds | Requiring 130 MB download |
| D12 | 2026-11-16 | Git author set to a neutral local identity | Avoid publishing the entrant's e-mail before they choose an identity | — |
| D13 | 2026-11-16 | Resolve free-text reports deterministically over the graph, abstain when ambiguous | Wrong-but-confident lift ids are the worst failure for a planner; retrieval over SERVES edges is explainable | LLM-only entity extraction |
| D14 | 2026-11-16 | Agent access through MCP on a read-only Relate connection | Relate allows many read-only processes beside the app; the agent can't write even via Cypher | Giving the agent the web API's write endpoints |
| D15 | 2026-11-16 | Keep every level of multi-stop lifts | Text lists 3 levels for some lifts; dropping the 3rd lost real connections | Keep first two sides only (old behaviour) |
| D16 | 2026-11-16 | Region layer from GTFS boardable platforms, journeys = ordered station pairs, exact reachability | Whole-network question needs whole-network data; exact counts keep rankings deterministic | Sampling OD pairs; Relate `SHORTEST` QPP per pair (one pair took > 5 min — Cypher kept for per-leg verification) |
| D17 | 2026-11-16 | A listed outage without topology makes a platform DOUBT, never CLOSED | The PRIM feed carries no redundancy information; inventing it would fake blocked journeys | Treating every listed outage as blocking |
| D18 | 2026-11-16 | Keep three views side by side instead of picking one "truth" | The two official feeds disagree; the disagreement is itself the finding | Silently preferring SNCF |
| D19 | 2026-11-16 | Ignore the feed's own line links when placing an outage | Independent check showed them incomplete (3/40 wrong placements) | Trusting feed links |
| D20 | 2026-11-16 | Boarding point = platform × line | GTFS has one rail platform per station; an RER A lift outage must not close RER D platforms | Platform-level states |
| D21 | 2026-11-16 | PRIM token only from env var / file outside the repo; normalized snapshot (no token) committed | Judges run offline; the secret never leaves the entrant's machine | `.env` in the repo |
| D23 | 2026-11-16 | Re-derive region reach in Cypher by set-at-a-time BFS (one query per round) | Relate answers each round in ~50 ms; exhaustive agreement on all origins makes the Python counts auditable | Path-pattern `SHORTEST` per pair (minutes) |
| D24 | 2026-11-16 | Ridership as context, never as the ranking metric | Validations count all riders (not wheelchair users) and miss gate-less tram stops; mixing them into gains would mislead | Weighting gains by validations |
| D22 | 2026-11-16 | Region "chokepoints" built, measured and dropped | Only 3 single platforms cut journeys between other stations; impact comes from combinations of outages | Shipping a feature with no signal |
| D25 | 2026-11-17 | Use IDFM « État des ascenseurs » for RATP lifts in the best view, read on a per-station lift graph | Fresh (3×/day), per-lift, says which levels each lift joins; the PRIM messages were frozen and redundancy-blind | Keep PRIM for RATP; treat each listed RATP outage as blocking |
| D26 | 2026-11-17 | Night snapshots: a lift switched off since 23:00 counts as UNKNOWN, not UNAVAILABLE | 163 of 188 RATP "failures" at 01:26 were end-of-service switch-offs; calling them outages would invent 100+ repairs | Ignoring the snapshot time; refusing night snapshots |
| D27 | 2026-11-17 | Rider alerts stateless on the server; trips kept in the rider's browser or in their own file | No personal data on the server; the CLI fits a scheduled task the rider controls | Accounts and server-side subscriptions |
| D28 | 2026-11-17 | Equal repair gains ordered by daily station use | Most repairs give back one station (same gain); the busier station helps more people. Gains stay the ranking metric (D24) | Weighting gains by ridership |
| D29 | 2026-11-17 | Second region from national data only (SNCF NeTEx + national GTFS + SNCF status + Fréquentation), boardability from the NeTEx station flag | Shows the method is not tied to IDFM-only sources; the national GTFS has no `wheelchair_boarding` | A metro network with a city-specific feed (would prove less about generality) |
| D30 | 2026-11-17 | Fix the track tokenizer for « Voies A et S » and exits named beside a track | Found while generalising; also wrong in Île-de-France (track A dropped, hall lost) | Region-specific parsing rules |
| D31 | 2026-11-17 | A lift not reported working at a station with no modelled platform↔street route → DOUBT | Building every region showed most stations have no exit named in the lift text; treating them as OPEN silently ignored real outages (Hauts-de-France read 100 % with 7 lifts out) | Leaving them OPEN; marking them CLOSED |
| D32 | 2026-11-17 | All mainland regions from national data, published with a per-region quality column | The comparison is only honest if the reader sees how much of each region's topology is modelled | Publishing only the regions that look good |
| D33 | 2026-11-17 | Zero-install demo = exported snapshot + browser engine + Relate WASM re-check, clearly labelled | Judges rarely clone; Relate's WebAssembly build keeps the graph engine in the loop; the browser engine is checked identical to the server's (1,038 reaches, 600 journeys) | A hosted server (cost, keys, uptime); screenshots only |
| D34 | 2026-11-17 | History recorded semi-automatically twice a day (Claude reminders), no scheduled task on the entrant's PC | The entrant asked for no permanent system configuration; daytime fetches avoid night switch-offs | Windows Task Scheduler; hourly fetches |
| D35 | 2026-11-17 | Trip subscriptions as stateless RSS / iCalendar URLs | Riders keep control; no accounts, no stored personal data | E-mail/SMS sending (needs accounts and consent handling) |
| D36 | 2026-11-17 | Field reports (riders, staff, AI agents) stored in the Relate graph as `(:FieldReport)-[:ABOUT]->(lift)`, written only through the server, never changing the official status or any count; set against the status the best view uses, with IDFM's status too when the two official sources differ | The hackathon theme is agents sharing a graph; Relate allows one writer, so every agent writes through the server and reads the same memory; an unverified report must not move a journey count | Letting reports override the status; a separate database for reports; each MCP process writing its own copy |
| D37 | 2026-11-17 | The live demo is rebuilt hourly by GitHub Actions (history committed every 3 hours), with the API keys as repository secrets; it publishes nothing without them | Supersedes D34 once the secrets are set: no computer of the entrant involved, and a demo that is never more than an hour old | Keeping the twice-a-day manual refresh; a hosted server |
| D38 | 2026-11-24 | Recover stop-place départements from open data when the NeTEx id carries none (national GTFS + UIC + Fréquentation postcode, DRG-checked; IDFM GTFS + ZdC postalregion as fallback); normalise new-style lift ids to their uuid | The 24 Nov 2026 SNCF file dropped the INSEE code from StopPlace ids and qualified lift ids, emptying every region build; coordinates alone locate nothing without a boundary dataset, while the UIC/postcode chains re-derive 98.75 % of départements with evidence | Hard-coding commune coordinates; nearest-neighbour guessing; a frozen uuid→département snapshot |
